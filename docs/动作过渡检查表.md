# 38组动作的进入、保持与结束检查表

本表依据`Actions.All`逐项审查。用户本轮要求每个动作都能从站立进入，并在结束后通过身体动作回到站立；两张立绘之间的淡化不能替代身体过程。动作正在站立时，可以沿用同一个站姿，不为了凑过渡增加一次无意义的动作。

这里记录审查时发现的入口、资源与本轮接入路径，**不表示以下动作已经通过画面或人工验收**。最终实际执行结果统一写入[验证记录](验证记录.md)，本表不登记通过数量。逻辑路线通过也不能证明新图集的关节、五官、鞋底、透明边缘或视觉流畅度通过。

## 共用约定

基础图集`assets/rin/poses.png`有12个单独姿势：0站立、1微笑、2看天、3整理衣摆、4持板、5伸手、6抱膝、7坐姿、8侧卧、9站立闭眼、10举手、11跪地。它们不是12段独立连续动画。

普通姿态由Behavior内的`ActionBridgeState`登记进入和退出路线。进入从0到目标姿态，退出先回0，再进入下一个姿态；抱膝6经过跪姿11，侧卧8经过11、6。`Bridge.Route/SegmentIndex/Progress/FromPose/ToPose`为逻辑检查点，角色保持时钟在过渡期间冻结。新`bridge-ground-v1.png`、`bridge-seat-v1.png`、`bridge-upper-v1.png`提供32个完整身体中间姿态，`action-bridge-art.json`登记它们的裁切/比例/根/控制点，`pose-bridges.json`登记原基础姿态。连续不透明变形只连接相邻实际关键画面；不能从站立直接大幅扭成跪卧，不能仅因逻辑路线列出了中间姿态就宣称画面通过。实现见[动作起止过渡](动作起止过渡.md)。

Nurture、秋千、平板、轻跃/转身和已有动作收尾继续由原有专用时序负责。通用过渡不得与它们争夺同一身体。登山由Journey自己的路线、换重、山顶/山脚收脚及站姿交接负责。所有时间仍来自Behavior唯一调度，不保存半段过渡，不新增成长或布局字段。

38个动作ID已由本轮152组逻辑检查覆盖；对应数据和最终绘图结果见验证记录。各行最后一列标注的是**人工体验仍待验收**，不是自动检查的结果。出现“已有”只表示代码或素材中存在对应内容；自动路线覆盖不代表每个动作、所有组合都已逐帧人工认可。

## 入口与中断核对清单

- 自主日常：idle/context结束先回站，随后才抽取新动作；自主创造的准备阶段不得触发创建事件。
- 动作页：重复选当前动作不重启；过渡期间连续选不同动作只执行最后一次，恢复过程不来回重置。
- 直接入口：托盘/右键/图鉴中的登山、草地、秋千、记忆、理想世界，以及直接点击长椅/鸟/床/窗/圆几，都不得绕过对应身体恢复。
- 平板：创造/消息/预选景物只保留最后请求；暂停、隐藏、锁屏、全屏或完全穿透后不补开界面，不提前消耗邀请次数。
- 登山：正常登顶后完整下山；山顶点击、结束观景、选其他动作/创造/消息分别检查实际回程；下山中重复请求不重启山径。
- 强中断：拖动立即跟手，保留抓取的实际身体；模式/场景/整理/支持物失效清理旧路线与请求，不在新布局中重播。
- 冻结：零时间、暂停、隐藏、锁屏和全屏不推进普通身体时序；恢复延续原进度。待开平板按前项单独取消。
- 存档：成长/自由与各场景布局、来信、次数和版本1保存契约不受瞬态身体过渡影响。

## 检查层次和当前记录边界

新增`tests/AllActionBridgeTests.cs`通过生产主项目引用驱动Behavior，预备检查38个ID的路线覆盖、起止姿态、支持中间姿态、时间冻结、30/60Hz、自然结束、重复/最后请求及拖动/模式/场景取消。专用时序检查实际走过的扶绳/起坐、趴卧/起身、拿板/收板、收尾、上山/下山阶段，而非把所有动作强行算作通用Bridge。

最终程序的逻辑、相邻姿态变形机制与生产绘图分别由`AllActionBridgeTests`、`ActorPoseWarpTests`、`ActionBridgeVisualTests`及原专用套件检查，本表不预写结果。需要核对透明边缘、完整人物尺度、肩髋/膝踝/手腕连接、支撑鞋底、臀部接触、同姿态端点与左右朝向；再由用户实际体验核对连续性。离屏1.0/1.5/2.0密度图像不等于Windows真实DPI、多屏、原生鼠标或一小时稳定性通过。新实际素材的绘图复核不能沿用先前原型的通过结果，实际执行与剩余范围见[验证记录](验证记录.md)。
